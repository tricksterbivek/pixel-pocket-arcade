# SuiteReact

> Build an **interactive React UI that runs inside NetSuite**, served by a **SuiteScript 2.1 Suitelet** and deployed with **SDF (SuiteCloud Development Framework)**.

SuiteReact is a starter that lets you ship a modern React + TypeScript single-page app *into* a NetSuite account. There is no separate web host, no CORS, and no token exchange — the app is served from a Suitelet and authenticated by the user's existing NetSuite session.

## How it works

```
Vite + vite-plugin-singlefile   →  one self-contained dist/index.html (all JS/CSS inlined)
        │
        ▼  scripts/inject-bundle.mjs
src/FileCabinet/.../ui.html      →  staged into the SDF File Cabinet tree
        │
        ▼  suitecloud project:deploy
NetSuite account                 →  Suitelet serves ui.html on GET, JSON data API on ?action=/POST
```

The **same** Suitelet multiplexes two responsibilities:

| Request | Response |
| --- | --- |
| `GET` (no `action`) | The full single-file React SPA (`text/html`). React Router takes over client-side. |
| `GET ?action=list\|get` / `POST` | JSON data API in a `{ ok, data \| error }` envelope. |

Auth is the in-browser NetSuite **session cookie**, so NetSuite enforces the logged-in user's record permissions on every query. See [`ARCHITECTURE.md`](./ARCHITECTURE.md) for the full design, data-flow diagram, API contract, and security notes.

## Project structure

```
app/                         React + TS source (built by Vite; never deployed)
  src/lib/suiteletClient.ts  fetch() wrapper for the JSON API
  src/pages/                 DashboardPage (list + filter + paging), RecordDetailPage
  src/components/            RecordsTable, FilterBar, ErrorBanner
  src/__tests__/             Vitest + React Testing Library
src/                         SDF project root (deployed to NetSuite)
  FileCabinet/SuiteScripts/SuiteReact/st_suitereact_ui.js   the multiplexed Suitelet
  Objects/customscript_st_suitereact_ui.xml                 script + deployment record
  manifest.xml, deploy.xml
scripts/inject-bundle.mjs    copies dist/index.html → File Cabinet ui.html
suitecloud.config.js         SDF CLI config (defaultProjectFolder: src)
```

## Prerequisites

- **Node.js** 18+ and npm
- **SuiteCloud CLI** for Node.js: `npm i -g @oracle/suitecloud-cli`
- A NetSuite account with the **SuiteCloud Development Framework** and **SuiteScript** features enabled, and a role with SDF deploy permission.

## Quickstart

```bash
npm install                 # install dependencies
npm run dev                 # local React dev server (data calls need a proxy/mock — see below)

# Deploy to NetSuite:
suitecloud account:setup    # one-time: authenticate the CLI to your account
npm run ship                # build + inject + suitecloud project:deploy
```

Then open the Suitelet's deployment URL in NetSuite (Customization → Scripting → Script Deployments → SuiteReact UI).

### npm scripts

| Script | What it does |
| --- | --- |
| `dev` | Vite dev server for the React app. |
| `build` | `tsc -b && vite build` → single-file `dist/index.html`. |
| `inject` | Copy `dist/index.html` → `src/FileCabinet/SuiteScripts/SuiteReact/ui.html`. |
| `bundle` | `build` + `inject`. |
| `deploy` | `suitecloud project:deploy`. |
| `ship` | `bundle` + `deploy` (the full pipeline). |
| `test` | Vitest. |
| `lint` | ESLint. |

### Local development note

`npm run dev` serves the SPA, but there is no Suitelet to answer `?action=list` calls locally. Either point `VITE_SUITELET_URL` at a deployed Suitelet (see `.env.example`), add a Vite `server.proxy`, or mock `app/src/lib/suiteletClient.ts` with fixtures.

## Customizing

- **Record types** exposed by the data API are governed by a **server-side allow-list** in `st_suitereact_ui.js` (`RECORD_TYPES`). Add your own record types and columns there — never trust a `type` from the client.
- The generated `ui.html` is a **build artifact** (git-ignored, regenerated by `npm run inject`).
